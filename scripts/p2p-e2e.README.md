# P2P 文件传输验收

本轮实现覆盖：

- P0：v2 完整目录扫描、空文件与空目录、整项失败策略，以及事务内撤回分享和提交后停止连接。
- P1：附件独立重试与会话绑定、文字先发及后台准备、账号加密任务记录与检查点、手动恢复、暂停/取消/停止分享、超时重试、源与接收位置重新关联。
- P2：分阶段进度、每页 50 条的传输中心、桌面通知、磁盘预检与迁移、多设备先后接收、附件移除入口和离线磁盘临时数据重试清理。

在仓库根目录执行：

```powershell
node scripts/p2p-e2e.mjs
```

需要先安装 `app/im-web` 的现有依赖。脚本使用项目已有的 Electron、Rolldown、Pinia 和生产代码，不新增依赖、不启动 HTTP 服务、不使用真实账号。Windows 环境需允许 Electron 创建自己的子进程；受限执行沙箱可能阻止 renderer 启动。

脚本创建三个隐藏 Electron 窗口，分别代表发送设备、接收设备和同一接收账号的另一台设备。每个设备使用独立临时存储，加载生产 preload、P2P store 和原生文件模块。文件内容经过真实 `RTCPeerConnection` / `RTCDataChannel`，再通过生产 IPC 写入真实磁盘文件；未配置 STUN、TURN 或文件中转。校验使用原始目录树和 SHA-256。

控制面使用符合服务端命令约定的内存实现，只传递消息摘要、设备声明、SDP、ICE 和控制信令。该验收不是在线 WebSocket/数据库集成测试，也不证明不同物理设备、跨子网、防火墙或 NAT 环境一定能直连。

## 场景

1. 文件夹包含非空文件、空文件、空目录和嵌套空目录；收到的目录树和内容哈希完全一致。
2. 完成后保留源；同一接收账号另一设备随后接收，原设备再次接收。
3. 完成源的发送实例销毁后重建，从持久化源重新注册并再次发送原始内容。
4. 64 MiB 文件在收到部分数据后手动暂停，接收实例销毁后重建；保持手动暂停及磁盘进度，继续后完整哈希一致。
5. 接收方取消仅结束当前尝试，分享仍可接收；模拟服务端撤回后活动接收停止且不能自动续传。
6. 64 MiB 文件传输中模拟信令断开并结束旧 route，重连后自动恢复检查点并完成；完整哈希一致。
7. 检查实际 RTC 接收的二进制字节，以及未配置中转服务器。

2026-09-09 11:42（北京时间）的实测结果为 **7/7 通过**，约 44 秒。手动暂停及接收实例重建前后均保留 131,072 字节；信令断开时保留 524,288 字节；两个 64 MiB 文件续传后均通过完整 SHA-256 校验。完成源重建后再次发送通过。结束后没有残留 Electron 进程或本次生成目录。

失败时报告包含状态快照、已通过场景、控制命令计数和错误堆栈。每次运行结果保存为 `app/im-web/.cache/p2p-e2e/latest.json`，该文件不应提交。默认清理本次生成的测试文件、构建文件和 Electron 实例。`--keep` 仅供排查时保留生成目录；`--build-only` 只验证打包。单次执行有 210 秒主进程及 240 秒启动器上限。

## 后端验证

在 `app/im-backend` 执行：

```powershell
mvn.cmd -pl im-server -am test
```

本轮后端完整测试通过 117 项，随后涉及能力限制的定向回归通过 23 项。覆盖分享持久化、撤回事务提交/回滚、路由结束幂等、旧路由重试不影响新路由、多设备顺序接收、暂停源、v1/v2 能力及摘要校验。迁移文件通过资源测试；本机 Docker daemon 未运行，没有可用的隔离数据库联调环境，因此没有在本轮将迁移应用到真实 MySQL 实例，也未启动现有部署或修改用户数据库。

真实 Electron 联调曾发现并修复：Vue 响应式对象无法直接经 IPC 保存、Electron MessagePort 传输列表导致本地数据封包为空、并发元数据保存覆盖最新磁盘检查点，以及信令重连时需要重新恢复原生接收通道。验收直接使用修复后的生产模块。

桌面端完整校验在 `app/im-web` 执行：

```powershell
npm run verify
```

最终执行通过：前端类型检查与生产构建、Electron 构建，以及 26 个测试文件中的 189 项测试。接收磁盘模块包含 27 项针对性测试，覆盖检查点、提交中断、损坏恢复、空目录、路径安全及磁盘离线等情形。最后补齐接收操作进度后，真实 Electron 7 个场景再次全部通过。

## 发布顺序

先部署支持 v2 的后端并执行 Flyway 迁移，再分发新桌面端。服务器继续兼容历史 v1 分享；新桌面端新建分享一律使用 v2，且要求服务器声明 v2 能力。不能把 v2 分享静默降级到 v1，空文件、空目录及目录摘要需保留 v2 语义。
